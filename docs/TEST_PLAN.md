# TEST PLAN

> 상태 표기: **통과**(자동 테스트 실행 결과) · **수동 필요**(사람이 실제 기기에서 확인해야 함) · **미완료** · **외부 의존**
> 실행하지 않은 시험을 통과로 적지 않는다.

## 1. 실행 명령

```bash
npm run typecheck                    # tsc --noEmit
npm run lint                         # oxlint
npm test                             # vitest run
npm run build && npm run test:e2e    # playwright (next start -p 3100 자동 실행)
```

E2E 환경: 컨테이너의 헤드리스 크로미움(Playwright 1.63), **GPU 없음 → SwiftShader 소프트웨어 WebGL**.
프로젝트 2개: `desktop`(1280×760), `mobile`(375×812, 터치).

## 3. 성능 — 측정값과 목표 구분

| 항목 | 측정값 | 측정 환경 | 목표 |
|---|---|---|---|
| 평균 FPS (3초) | **8~10 fps** | 헤드리스 크로미움 + SwiftShader(CPU 렌더), 1280×760, DPR 1 | 데스크톱 60fps, 중급 모바일 30fps — **수동 필요** |
| 그리기 호출 | 124 / 프레임 | 같음 (그림자 패스 포함) | < 300 |
| 삼각형 | 10,988 | 같음 | — |
| 텍스처 / 지오메트리 | 14 / 75 | 같음 | — |
| DOMContentLoaded | 22~81 ms | localhost, 운영 빌드 | — |
| 질감 총량 | 약 0.55 MB (JPG 10장) | 파일 크기 | — |

SwiftShader FPS는 GPU 성능을 나타내지 않는다. 실제 기기 측정이 필요하다.

## 4. 수동 확인 필요 (자동으로 못 한 것)

| 항목 | 이유 |
|---|---|
| GPU 있는 데스크톱에서 FPS·부드러움 | 컨테이너에 GPU 없음 |
| 실제 휴대폰(iOS Safari, Android Chrome)에서 터치 회전·핀치 | 에뮬레이션만 함 |
| 카메라 감도·관성·포커스 거리가 자연스러운지 | 사람의 판단 |
| 전환 중 비정상 변형·순간 이동이 없는지 눈으로 | 자동 테스트는 시작·끝 위치만 확인 |
| 모션 감소 설정 실제 동작 | 단위 테스트(0초)만 있음 |
